Path 1, the normal case: the API sends HTTP 409 with the code lot.on_hold and its values. The client finds the code in its errors file and formats the values, the user reads the message in their own language, and there is nothing to report. Path 2, a fallback: the API sends a code the client has no text for, or leaves out a value the text needs. In the sample line.changeover_in_progress is left without text on purpose, to show it. The user sees the server’s English detail, marked as English, and the code is listed on Translation status and fails the strict check. Path 3, a fallback: the API sends no code at all, only a title and an errors dictionary, which is ASP.NET Core’s default validation answer. There is nothing to translate, so the server’s own words are shown on the fields it names. It is counted nowhere, and is a dependency to raise before work starts. The stand-in API never does this, so only the screen tests cover it.
